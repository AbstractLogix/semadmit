# M0 Conformance Fixtures

These Semadmit contract fixtures are normative for v0.1. Independent M0 review approved them on 2026-09-30. The Haskell Isoprax executable passes its pool fixtures. Full cross-pack conformance and release checks remain open.

- `m0-identity-vectors.json` contains shared and first-party identity examples. It includes a property-order case where Unicode scalar ordering differs from RFC 8785 UTF-16 ordering.
- `isoprax-cases.json` records the Isoprax decision matrix. Cases include ASCII-normalized semantic equivalence with different display/raw metadata, exact non-ASCII comparison, populated threshold multiset permutations, duplicate-threshold mismatch, unknown threshold values, observation-process parameter mismatch, and valid window mismatch. The `artifacts_files` list points to size-bounded canonical artifact shards. The `calculations_file` points to reduced exact ECE values for every defined calibration calculation. Generated cases specify deterministic mutations, such as the sample-pair limit.
- `isoprax-legacy-number-adapter.json` records finite binary64-to-decimal adapter examples. It covers exponent expansion, precision/range boundaries, negative-zero mapping, and non-finite rejection. These are adapter inputs, not Semadmit request JSON numbers.
- `measurement-cases.json` and `measurement-artifacts.json` record measurement decisions, input errors, both evidence-order pairs, and canonical artifacts.
- `neutral-extension.json` defines a two-role extension pack. It checks registration, generic bindings, all three states, result verification, invalid pack output, and passing/failing evidence-order pairs.
- `protocol-cases.json` records exact parser errors and deterministic input recipes for resource limits and JSONL recovery. Errors use exact envelopes and pointers. They have no decision digest.
- `rfc8785-vectors.json` records the published Appendix B number samples, the Section 3.2.2 primitive/string example, and the Sections 3.2.3–3.2.4 property-order/UTF-8 example.
- `bouleusis-compatibility.json` records the exact merged Semadmit baseline, frozen claim/Core protocols, consumer contract label, and result-verification fixture. It is a Semadmit-owned compatibility record, not proof of a Bouleusis integration run.
- [Core parity corpus](../../test/integration/vertical_slice/vectors.json) is the selective Python/Haskell Core parity corpus. Both suites compare complete decisions against the same expected vectors. A disagreement fails the matching language suite. Claim and IsoPrax domain semantics are outside this shared corpus.

Decision case files contain complete requests. Artifact sidecars deduplicate canonical identity-envelope and decision bytes by digest. This includes the Isoprax shards listed by `artifacts_files`. Each expected digest resolves to an entry whose `id` is the SHA-256 digest of `canonical_utf8`. If an artifact omits `form`, it means `identity-envelope`. `form: decision` means decision payload bytes. The Isoprax calculation sidecar is a non-normative trace of internal ECE values. ECE is absent from decision payloads. Protocol recipes reference a complete measurement request. They define mutations, JCS serialization, padding, and nesting depth. This keeps large parser inputs out of inline fixture data.

During M0 preparation, an independent ECMAScript/V8 canonicalizer and `sha256sum` reproduced the stored canonical bytes and digests. The published JCS vectors test primitive serialization and UTF-16 property ordering. They are generic canonicalizer vectors. Semadmit request parsing rejects fractional, exponent-form, negative-zero, and unsafe-integer JSON tokens. Independent adversarial review approved the M0 contract and fixture package. These fixtures do not demonstrate product implementation conformance. The Ducky-specific contract and fixtures remain an M4 gate against the approved interface.
